## nginx 反向代理：配置模板 + 三条硬约束

用户拿**别的项目**的 nginx 配置（`location /treehole/bfd/`、`location /itgp/` 那种**子路径**风格）问 Talos 怎么配。
新增 `server/deploy/nginx/talos.conf`（随服务端包分发），README 加「六、用 nginx 暴露控制台」，
`package-server.bat` 增加 `nginx/` 目录拷贝（`*.conf` 已在 ps1 的 LF 组里，自动规范化）。

**⭐ Talos 不能挂子路径** —— 用户现有配置正是子路径风格，照搬必白屏：前端构建期就写死绝对路径，
API 基址 `/api`（`web/src/api.ts` 的 `BASE`）、资源 `/assets/xxx.js` 与 `/favicon.svg`（`web/dist/index.html`）。
挂 `/talos/` 下浏览器会去请求 `/api`、`/assets` → 全 404。要子路径必须先设 `server.servlet.context-path` 并重构建前端。
→ 只能靠**独立域名**或**独立端口**区分。

另两条：`client_max_body_size`（默认 1MB vs 上传上限 1GB —— 413 挡在 nginx 层、后端日志**全无记录**，
最容易被误判成前端 bug）、`proxy_read_timeout`（准入/分拣「录入即判」同步调 LLM，60s+ 常见，
沿用 60s 会先 504 而后端还在跑）。模板另含 `proxy_request_buffering off`（1GB 上传别先落 proxy_temp）、
`/assets/` 长缓存、`/h2-console/` 只放内网。

**gRPC 默认不走 nginx**：agent 建通道是 `usePlaintext()`（`AgentDaemon.serve`），明文 h2c 无 TLS，
**指到 443 会立刻握手失败** —— 客户端反复重连 + 日志 UNAVAILABLE，而 nginx 侧看不到任何错误请求，很隐蔽。
要统一入口只能用「明文 + 独立端口」：服务端 `TALOS_GRPC_PORT` 挪 19443（最好再 `grpc.server.address: 127.0.0.1`），
nginx `listen 9443 http2` + `grpc_pass grpc://`，**客户端 conf 不用改**。模板末尾有整段注释好的配置。

### 校验方法（可复用）
`D:/develop/tool/nginx.zip` 解压出 nginx.exe 1.19.4，给将要部署到 CentOS 的配置做**真实语法校验**，四招：
1. 路径改成相对**配置文件所在目录**（`ssl/dummy.crt` —— nginx 的 include 与证书相对基准是配置文件的目录，不是 prefix）
2. `listen` 临时换高位端口（80/443 本机占用时 `-t` 也会真 bind 并失败）
3. `openssl req -x509 ... -subj "//CN=x"` 生成自签证书（`-t` 会解析 PEM，假文件报 `PEM_read_bio`）
4. 顶层写最小 `nginx.conf` 用 `include` 引入待测片段
结果：主配置 `test is successful`，gRPC 段 `syntax is ok`（`grpc_pass` / `grpc_socket_keepalive` / `listen 9443 http2` 均被接受 → 该版本带 grpc 模块）。

1. **限流必须两张表**：`LoginCodeService` 里 `codes`（当前待验证码）与 `rates`（小时配额 + 上次发送时刻）

5. **联调开关** `talos.auth.expose-code: true` 时 `send-code` 响应里直接回码 —— 无头浏览器验证登录用，
