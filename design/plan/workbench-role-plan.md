# 我的工作台（按角色）设计方案

## 1. 背景与目标

现状：
- 侧栏「运营」组首项是「总览」（`dashboard`），展示**全局**流水线健康度，与登录人无关。
- 系统有六类角色（`admin` / `pm` / `lead` / `dev` / `qa` / `guest`）与能力矩阵，但**页面动作未按角色渲染**（已知待办）。
- 文案里提到「角色决定工作台可见能力」，产品上尚未落地。

目标：新增 **「我的工作台」** 作为登录后默认首页——**一人一面**，只展示「需要我处理 / 与我相关」的内容与动作；全局总览降级为管理员/负责人可选入口，不再人人默认。

非目标（本阶段不做）：
- 不全量改造侧栏 RBAC（可二期按能力矩阵隐藏菜单）。
- 不新做重型 BI；复用现有 Issue / 实例 / 客户端接口做聚合筛选。
- 不改准入/工作流引擎本身。

---

## 2. 信息架构

### 2.1 导航

| 项 | 说明 |
|----|------|
| 新页 key | `workbench` |
| 侧栏文案 | **我的工作台**（运营组第一项） |
| 原「总览」 | 保留 `dashboard`，文案改为「平台总览」；仅 `admin` / `lead` 默认露出，其余角色可从设置「默认首页」选到或侧栏折叠区进入 |
| 默认首页 | `settings.homePage` 默认值由 `dashboard` → `workbench` |

### 2.2 页面骨架（所有角色共用同一框架，内容插槽按角色切换）

```
┌─────────────────────────────────────────────────────────┐
│ 问候条：你好，{姓名} · {角色标签}     [角色主 CTA…]      │
├──────────┬──────────┬──────────┬──────────┤
│ KPI × 3~4（角色定制指标，可点击下钻）                    │
├────────────────────────────┬────────────────────────────┤
│ 主区：需要我处理            │ 辅区：与我相关 / 环境状态   │
│ （待办列表，按紧急度排序）  │ （进度、客户端、域健康等） │
├────────────────────────────┴────────────────────────────┤
│ 快捷入口（仅展示该角色有权限的 3~5 个动作）               │
└─────────────────────────────────────────────────────────┘
```

原则：
- **一屏一事**：主区永远是「待我动手」的列表，不做全站仪表盘堆砌。
- **卡片仅用于可点击 KPI / 待办行交互**，避免装饰性卡片墙。
- 空态文案按角色区分（如开发：「暂无指派给你的 Issue」）。

## 3. 身份与归属规则

工作台「与我相关」依赖当前登录人，需先理顺身份（现状缺口）：

| 字段 | 现状 | 方案 |
|------|------|------|
| `talos.profile.role` | 展示文案如「平台管理员」 | 增补 `roleCode: 'admin'\|…`，与 `t_user.role` 对齐；登录成功后从用户表回填 |
| 姓名 / 工号 | localStorage profile | 与 `t_user.name` / `empNo` 对齐；匹配 Issue 时**工号优先、姓名兜底** |
| 业务域 | `UserRow.bizCodes` | 用于 lead/pm 的「我域内」过滤 |
| 客户端 | `UserRow.clientId` | 用于 dev 的「我的终端」状态 |

**Issue 归属判定（前端筛选，首期）**

| 关系 | 判定 |
|------|------|
| 我提报的 | `issue.reporter` ∈ {name, empNo} |
| 我承接的 | `issue.owner` ∈ {name, empNo} |
| 我域内的 | `issue.bizCode` ∈ 用户 `bizCodes`（或沿业务树匹配） |
| 跑在我机器上的 | `issue.clientId` === 用户绑定客户端 |
| 待我评审/测试 | 状态 ∈ {`reviewing`, `blocked`} 且（owner=我 **或** 当前节点 kind=`rev`/`test` 且实例 client/owner 关联到我）——首期用状态+owner 近似，二期接节点级指派 |

首期不强制新后端接口；数据量可控时用现有 `GET /api/issues`、`/workflow/instances`、`/clients`、`/users` 客户端聚合。若列表变大，再补 `GET /api/workbench/summary`。

## 4. 分角色内容矩阵

### 4.1 产品 `pm`

**一句话**：盯住我提的单，从准入到交付。

| 区块 | 内容 |
|------|------|
| KPI | 我提报未闭环 · 准入中/驳回 · 执行中 · 阻塞待关注 |
| 主区「需要我处理」 | 被驳回需改提 · 准入失败 · 阻塞且与我相关 · 待我补充材料 |
| 辅区 | 我提报的近期进度时间线（状态变更摘要） |
| 主 CTA | 新建 Issue |
| 快捷入口 | Issue 列表 · 准入判定（只读/查看） · 文档中心 |

### 4.2 技术负责人 `lead`

**一句话**：域内分拣、阻塞与节奏。

| 区块 | 内容 |
|------|------|
| KPI | 域内待分拣 · 域内阻塞 · 域内执行中 · 域内离线客户端（有绑定的） |
| 主区 | 待分拣 / 候选域歧义 · 阻塞需拍板 · 评审待决 |
| 辅区 | 域内工作流实例健康（按业务域聚合） |
| 主 CTA | 去分拣 / 打开阻塞 Issue |
| 快捷入口 | Issue · 作业监控 · 业务域 · 工作流编排 |

### 4.3 开发 `dev`

**一句话**：我的任务 + 我的终端。

| 区块 | 内容 |
|------|------|
| KPI | 指派给我未闭环 · 执行中 · 阻塞 · 我的客户端在线状态 |
| 主区 | 指派给我且需推进（含 blocked/reviewing）· 跑在我客户端上的实例 |
| 辅区 | 我的客户端：在线/版本/最近心跳；未绑定则引导去设置绑定 |
| 主 CTA | 打开当前执行中的 Issue / 绑定客户端 |
| 快捷入口 | Issue（我的）· 作业监控 · 接入指南 · Coding Agent 配置 |

### 4.4 测试 `qa`

**一句话**：验收与测试节点。

| 区块 | 内容 |
|------|------|
| KPI | 评审待决 · 测试阶段 Issue · 近期已验收 · 阻塞（测试相关） |
| 主区 | `reviewing` / 测试节点待处理 · 需我确认的文档 |
| 辅区 | 近期完成验收列表 |
| 主 CTA | 进入待验收 Issue |
| 快捷入口 | Issue · 文档中心 · 作业监控 |

### 4.5 管理员 `admin`

**一句话**：平台是否健康，谁卡住了。

| 区块 | 内容 |
|------|------|
| KPI | 全站待处理 Issue · 活跃实例 · 离线客户端 · 近 24h AI 调用异常（有则显示） |
| 主区 | 跨角色告警合集：阻塞 · 离线客户端 · 权限/配置缺失类提示（若有） |
| 辅区 | 精简版平台总览（或入口卡片「打开平台总览」） |
| 主 CTA | 平台总览 / 用户管理 |
| 快捷入口 | 用户 · 权限 · 客户端 · 模型配置 |

> 管理员工作台 ≠ 复制现有总览；总览保留深度指标，工作台强调「该我管的异常」。

### 4.6 访客 `guest`

**一句话**：只读旁观。

| 区块 | 内容 |
|------|------|
| KPI | 可见 Issue 数 · 执行中 · 已完成（只读） |
| 主区 | 可见范围内的近期 Issue（无操作按钮） |
| 辅区 | 只读说明：「访客无法录入或执行」 |
| 主 CTA | 无；或「联系管理员开通角色」 |
| 快捷入口 | 文档中心（只读） |

## 5. 交互与下钻

- KPI / 待办行点击 → `nav(page, focus)`，复用现有 `PageFocus`（`issueCode` / `status` / `clientId` / `offline` 等）。
- 新增 focus 建议（实现时补类型）：
  - `mine: true` — Issue 页筛「与我相关」
  - `scope: 'reported' \| 'owned' \| 'biz'` — 细分
- 待办排序：阻塞 > 驳回 > 评审待决 > 执行中 > 其他；同级按 `due` / 更新时间。
- 列表每行：标题 · 状态 Tag · 业务域 · 相对时间；右侧弱操作（打开 / 去监控）。

## 6. 权限与动作显隐

首期在工作台内按 `roleCode` + 能力矩阵硬编码「主 CTA / 快捷入口」显隐，与 `DataInitializer` 矩阵对齐：

| 动作 | admin | pm | lead | dev | qa | guest |
|------|-------|----|------|-----|----|-------|
| 新建 Issue | ✓ | ✓ | △ | ✓ | △ | ✗ |
| 分拣/改派 | ✓ | △ | ✓ | � | ✓ | △ | ✗ |
| 分拣/改派 | ✓ | △ | ✓ | ✗ | ✗ | ✗ |
| 启停客户端 | ✓ | ✗ | △ | ✗ | ✗ | ✗ |
| 用户/权限 | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ |

（✓ 完整 · △ 部分/视场景 · ✗ 不展示）

二期：侧栏整组按能力过滤；工作台快捷入口改为读 `/api/roles` 动态生成。

## 7. 实现切片（建议）

### Phase A — 可演示（优先）

1. 身份：`Profile` 增加 `roleCode`；登录/选用户后写入；提供 `useCurrentUser()`（profile + `fetchUsers` 匹配）。
2. 新页 `Workbench.tsx` + `PageKey` / NAV / TITLE / 默认 `homePage`。
3. 六套内容配置表（KPI + 主区过滤器 + CTA），同一套 UI 壳渲染。
4. `dashboard` 改称「平台总览」，admin/lead 侧栏保留。

### Phase B — 体验加固

1. Issue 页支持 `focus.mine` / `scope`。
2. 开发辅区「我的客户端」深度（日志入口、版本落后提示）。
3. 空态与引导（未绑定客户端、未分配业务域）。

### Phase C — 后端聚合（可选）

1. `GET /api/workbench`：服务端按 empNo/role/bizCodes 返回 summary + todo[]，减少前端拉全量。

## 9. 验收标准

1. 用不同角色账号（或切换 `roleCode`）进入控制台，工作台 KPI/待办/CTA **肉眼可区分**。
2. 开发未绑定客户端时，辅区明确引导绑定；绑定后显示在线状态。
3. 产品新建 Issue CTA 可用；访客看不到新建。
4. 默认登录落到「我的工作台」而非平台总览。
5. 点击待办能落到 Issue/监控正确筛选，不出现「暂无数据」假空（需带上 focus）。

---

## 10. 开放问题（实现前可拍板）

1. **平台总览**是否对 pm/dev/qa **完全隐藏**，还是放在侧栏底部「更多」？
2. 登录尚未接真 SSO 时，是否在工作台顶栏提供 **「预览角色」** 切换（仅内网调试）？
3. lead 的「域内」是否包含子业务域（沿 `parentCode` 树展开）？建议：**是**。

---

## 11. 结论

「我的工作台」= 角色化待办首页，不是第二块全局大盘。  
先做 Phase A（前端聚合 + 六套配置），把「一人一面」立起来；侧栏全量 RBAC 与后端 summary 放到后续迭代。
