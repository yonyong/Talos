# 我的工作台（按角色）设计方案

## 1. 背景与目标

现状：
- 侧栏「运营」组首项是「总览」（`dashboard`），展示**全局**流水线健康度，与登录人无关。
- 系统有六类角色（`admin` / `pm` / `lead` / `dev` / `qa` / `guest`）与能力矩阵，但**页面动作未按角色渲染**（已知待办）。
- 用户表原先单值 `role`，无法表达一人多岗。

目标：新增 **「我的工作台」** 作为登录后默认首页——**按当前激活角色**展示「需要我处理 / 与我相关」；一人可拥有多角色并在工作台一键切换；全局「平台总览」仅对具备 `admin` / `lead` 的激活角色可见。

非目标（本阶段不做）：
- 不全量改造侧栏其余菜单的 RBAC（二期）。
- 不新做重型 BI；复用现有 Issue / 实例 / 客户端接口做聚合筛选。
- 不改准入/工作流引擎本身。

---

## 2. 已拍板决策

| # | 议题 | 结论 |
|---|------|------|
| 1 | 平台总览对 pm/dev/qa/guest | **完全隐藏**（侧栏不出现）；仅当前激活角色为 `admin` 或 `lead` 时显示 |
| 2 | 角色模型 | **一人可多角色**；工作台问候条提供角色切换；内容与「平台总览」显隐跟随**当前激活角色** |
| 3 | lead「域内」范围 | **包含子业务域**（沿 `parentCode` 向下展开） |

## 3. 信息架构

### 3.1 导航

| 项 | 说明 |
|----|------|
| 新页 key | `workbench` |
| 侧栏文案 | **我的工作台**（运营组第一项） |
| 原「总览」 | 改称 **平台总览**（`dashboard`）；仅 `activeRole ∈ {admin, lead}` 时渲染侧栏项 |
| 默认首页 | `settings.homePage` 默认 → `workbench`；Logo 点击回工作台 |
| 误入守卫 | 若 URL 停在 `dashboard` 但当前激活角色无权，自动重定向到 `workbench` |

### 3.2 页面骨架

```
┌─────────────────────────────────────────────────────────┐
│ 你好，{姓名}  [角色芯片可切换…]          [角色主 CTA…]   │
├──────────┬──────────┬──────────┬──────────┤
│ KPI × 3~4（随 activeRole 变）                            │
├────────────────────────────┬────────────────────────────┤
│ 主区：需要我处理            │ 辅区：与我相关 / 环境状态   │
├────────────────────────────┴────────────────────────────┤
│ 快捷入口（随 activeRole）                                 │
└─────────────────────────────────────────────────────────┘
```

原则：一屏一事；主区=待我动手；空态按角色文案区分。

## 4. 多角色数据模型

### 4.1 后端 `t_user`

| 字段 | 说明 |
|------|------|
| `roles` | 新增，`List<String>`，逗号分隔持久化（复用 `StringListConverter`），如 `admin,lead` |
| `role` | **保留**为「主角色」= `roles[0]`，兼容旧查询 / 请求头；读写时与 `roles` 同步 |

规则：
- 保存时若带 `roles`（含空数组），以它为准，并写回 `role = roles[0]`（空则 `guest`）。
- 读取时若 `roles` 空，则 `roles = [role]`。
- `GET /api/users?role=dev`：返回 `roles` 包含该角色的用户（不再要求主角色精确等于）。

### 4.2 前端身份

```ts
Profile {
  name, no, email, phone
  roles: RoleCode[]      // 拥有的全部角色
  activeRole: RoleCode   // 当前激活（工作台/总览显隐用）
  role: string           // activeRole 的中文标签（兼容旧展示）
}
```

- `activeRole` 持久化在 `talos.profile`；切换时广播 `talos:active-role`。
- 若服务端 `roles` 变更导致当前 `activeRole` 不在列表中，回落到 `roles[0]`。
- 登录成功：按账号/工号匹配 `t_user`，回填 name/no/roles；`activeRole` 若仍合法则保留，否则取首项。

### 4.3 切换交互

- 工作台问候条：多角色时展示一排角色芯片（`Chips`）；单击切换 `activeRole`，KPI/待办/CTA 立即刷新。
- 仅一角色时只显示标签，不可点。
- 用户管理：角色由单选改为**多选**；列表「角色」列展示全部标签。

## 5. 身份与归属规则

| 关系 | 判定 |
|------|------|
| 我提报的 | `reporter` ∈ {name, empNo} |
| 我承接的 | `owner` ∈ {name, empNo} |
| 我域内的 | `issue.bizCode` ∈ **expand(用户 bizCodes)**（含子域） |
| 跑在我机器上的 | `issue.clientId` === 绑定客户端 |
| 待我评审/测试 | 首期：`reviewing`/`blocked` + owner=我 |

`expand(codes)`：给定业务域编码集合，并入所有 `parentCode` 链下落在该集合下的子孙编码。

首期前端聚合现有 API；量大后补 `GET /api/workbench`。

## 6. 分角色内容矩阵（随 activeRole）

### 6.1 产品 `pm`
盯住我提的单。KPI：我提报未闭环 · 准入中/驳回 · 执行中 · 阻塞。主区：驳回/阻塞/待补充。CTA：新建 Issue。

### 6.2 技术负责人 `lead`
域内分拣与阻塞（**含子域**）。KPI：域内待分拣 · 阻塞 · 执行中 · 相关离线客户端。CTA：处理阻塞 / 去 Issue。

### 6.3 开发 `dev`
我的任务 + 终端。KPI：指派未闭环 · 执行中 · 阻塞 · 客户端在线。辅区：客户端状态/绑定引导。

### 6.4 测试 `qa`
验收。KPI：评审待决 · 测试中 · 已验收 · 阻塞。CTA：进入待验收。

### 6.5 管理员 `admin`
平台异常。KPI：全站待处理 · 活跃实例 · 离线客户端 · AI 调用量。辅区入口：打开平台总览。

### 6.6 访客 `guest`
只读可见 Issue；无新建等写操作。

## 7. 权限与动作显隐（按 activeRole）

| 动作 | admin | pm | lead | dev | qa | guest |
|------|-------|----|------|-----|----|-------|
| 新建 Issue | ✓ | ✓ | △ | ✓ | △ | ✗ |
| 分拣/改派 | ✓ | △ | ✓ | ✗ | ✗ | ✗ |
| 平台总览入口 | ✓ | ✗ | ✓ | ✗ | ✗ | ✗ |
| 用户/权限 | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ |

说明：首期**工作台内容与侧栏总览**跟激活角色走；API 写权限仍按既有网关逻辑（二期可改为角色并集）。

## 8. 实现切片

### Phase A（本迭代）

1. 后端 `roles` 字段 + 保存/列表兼容；种子用户示范多角色（如杨德 `admin,lead`）。
2. `Profile.roles` / `activeRole`；用户管理多选角色。
3. `Workbench.tsx` + `workbench.ts`；NAV / 默认首页 / 总览显隐。
4. lead 域过滤含子域。

### Phase B

1. Issue `focus.mine` / `scope`。
2. 开发辅区客户端深度；空态引导打磨。

### Phase C

1. `GET /api/workbench` 服务端聚合。

## 10. 验收标准

1. 多角色用户可在工作台切换角色，KPI/待办/CTA 随之变化。
2. 激活 `pm`/`dev`/`qa`/`guest` 时侧栏**无**「平台总览」；切到 `admin`/`lead` 后出现。
3. lead 能看到子业务域 Issue。
4. 默认登录进入「我的工作台」。
5. 用户管理可给一人勾选多个角色并持久化。

---

## 11. 结论

「我的工作台」= 随**激活角色**变化的待办首页；一人多角色通过芯片切换，不靠调试用的「预览角色」。平台总览对非 admin/lead 激活态隐藏。
